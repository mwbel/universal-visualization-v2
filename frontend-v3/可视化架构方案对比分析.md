# 可视化架构方案对比分析：规则驱动 vs 模型驱动

本文档旨在对比分析“万物可视化”项目中两种不同的技术架构方案，分析其优缺点、实现难度及适用场景，并对当前架构提供优化建议。

## 1. 方案定义

### 方案 A：混合模式 (当前架构)
**流程**：`本地模板匹配` -> `LLM 生成 (如果有 Key)` -> `通用 Mock 生成`

*   **本质**：**“特权通道” + “兜底机制”**。
*   **逻辑**：
    1.  **VIP 通道 (Local Template)**：对于高频、核心的关键词（如“指数分布”、“太阳系”），系统直接拦截，返回预置的、经过精心调试的高质量 HTML 模板。
    2.  **AI 通道 (LLM)**：如果未命中 VIP 通道，则将请求发送给大模型（Gemini/GLM/OpenAI），由 AI 动态生成代码。
    3.  **Mock 通道 (Fallback)**：如果用户未配置 API Key 或 API 调用失败，使用通用 Mock 逻辑生成基础图表。

### 方案 B：纯 AI 路由模式
**流程**：`本地学科路由` -> `LLM 生成 (如果有 Key)` -> `返回前端`

*   **本质**：**“纯 AI 代理 (Agent)”**。
*   **逻辑**：
    1.  **路由 (Router)**：前端仅负责识别用户意图所属的领域（如“物理”、“数学”、“天文”）。
    2.  **Prompt 组装**：根据识别的领域，加载对应的 System Prompt（提示词）。
    3.  **生成 (Generation)**：完全依赖 LLM 现场编写 HTML/JS 代码来实现可视化。

---

## 2. 深度对比

| 维度 | 方案 A (混合模式) | 方案 B (纯 AI 路由) |
| :--- | :--- | :--- |
| **响应速度** | **极快** (本地模板毫秒级) | **慢** (依赖 API 网络耗时，通常 3-10秒) |
| **稳定性** | **极高** (预置代码，不会出错) | **中等** (AI 代码可能存在语法错误或样式问题) |
| **交互质量** | **最佳** (可深度定制 UI 和交互控件) | **随机** (取决于 AI 此时的发挥) |
| **覆盖范围** | 有限 (仅覆盖预设场景) | **无限** (理论上支持任何文本输入) |
| **API 成本** | **低** (核心高频功能 0 消耗) | **高** (每次请求都需要 Token) |
| **开发维护** | 需手动编写和维护模板文件 | 仅需维护 Prompt，开发工作量较小 |

---

## 3. 实现难度分析

### 如果目标是“开发省事” (MVP 阶段)
👉 **方案 B (纯 AI 路由) 胜出**
*   **优势**：无需编写复杂的 D3.js 或 Plotly.js 前端代码。只需要写好 Prompt（如“你是一个物理可视化专家...”），剩下的工作全交给大模型。
*   **代价**：用户体验不可控，且必须依赖 API Key。

### 如果目标是“产品体验最佳” (生产环境)
👉 **方案 A (混合模式) 胜出**
*   **优势**：
    *   **教科书级体验**：对于“正态分布”、“二阶行列式”等标准教学内容，预置模板可以提供完美的滑块交互、公式联动，这是 AI 难以一次性完美生成的。
    *   **长尾覆盖**：对于“分析一下我的午饭营养成分”这种非标准需求，自动降级由 AI 处理，保证了“万物可视化”的承诺。

## 4. 当前代码架构现状 (`ApiClient.js`)

目前项目实际上采用了 **方案 A (混合架构)**，结合了二者的优点：

1.  **第一道防线：精确匹配 (`matchLocalTemplate`)**
    *   直接拦截 `visualization_templates.js` 中已有的 10+ 个模板。
    *   *代码位置：ApiClient.js Line 197*

2.  **第二道防线：学科路由 (`getSystemPrompt`)**
    *   当本地模板未命中时，根据关键词判断领域（物理/天文/数学），为 LLM 注入专业背景知识。
    *   *代码位置：ApiClient.js Line 338*
    *   *这实际上包含了方案 B 的核心逻辑。*

## 5. 建议与演进路线

鉴于应用口号是 **“万物可视化，一图胜千言”**，建议 **保持并优化当前的混合架构**：

1.  **坚持“二八定律”**：
    *   将最常问的 20% 知识点（如高中数学、物理经典模型）固化为本地模板，确保核心体验。
    *   剩下的 80% 长尾需求交给 AI。

2.  **优化学科路由**：
    *   目前的 `getSystemPrompt` 路由逻辑基于简单关键词。
    *   **改进建议**：可以扩展 `PromptTemplates.js`，增加更多学科分类（如化学、生物、经济学），让 AI 在处理未知领域时更加专业。

3.  **完善 Mock 兜底**：
    *   当用户既没有 API Key 也没命中模板时，Mock 数据应尽可能丰富，避免让用户看到空白或报错（这也是我们刚刚修复指数分布 Mock 问题的初衷）。

## 6. 架构升级：离线工具箱 (MockEngine)

**更新时间**：2025-12-07

为了进一步增强系统的鲁棒性，特别是解决无 API Key 环境下的体验问题，我们引入了 **MockEngine**，将其打造为一个强大的“离线工具箱”。

### 6.0 概念定义：什么是 Mock？

**Mock**（模拟）在软件工程中通常指为了测试或替代真实功能而制造的“仿真品”。在本项目中，Mock 扮演了**“离线替身”**的角色：

*   **真实情况 (Real)**：
    用户输入 "画一个正弦波" -> 发送给 GPT-4 -> 等待 3-5 秒 -> 消耗 $0.05 -> AI 生成一段全新的 HTML 代码 -> 返回给前端。
*   **Mock 情况 (Simulation)**：
    用户输入 "画一个正弦波" -> `MockEngine` 拦截 -> **0 延迟** -> **0 费用** -> 识别到关键词 "正弦" -> 直接调出预存好的 `sin_wave` 模板 -> 返回给前端。

**为什么要用 Mock？**
1.  **省钱 (Cost)**：高频、简单的基础概念（如数学函数、排序算法）不需要每次都问 AI，用 Mock 免费生成。
2.  **极速 (Speed)**：AI 生成需要几秒钟，Mock 是毫秒级的，体验极其流畅。
3.  **离线可用 (Offline)**：即使用户没有网络，或者 API Key 失效了，系统依然能通过 Mock 引擎响应大部分基础指令，不会“瘫痪”。
4.  **兜底 (Fallback)**：当 AI 服务挂掉或报错时，Mock 可以作为备用方案顶上。

### 6.1 核心变革
我们将原有的 `if-else` 简单 Mock 逻辑重构为基于 **策略模式 (Strategy Pattern)** 的独立引擎 (`js/utils/MockEngine.js`)。

*   **解耦**：Mock 逻辑不再耦合在 `ApiClient` 中，便于独立维护。
*   **扩展**：新增学科只需注册新的策略对象，无需修改主流程。

### 6.2 能力矩阵 (离线可用)
目前的 Mock 引擎已不仅仅是“兜底”，而是覆盖了 8 大高频场景的**专家系统**：

| 领域 | 触发关键词示例 | 可视化内容 | 交互特性 |
| :--- | :--- | :--- | :--- |
| **📐 数学** | `二次函数`, `抛物线` | **$y=ax^2+bx+c$ 图像** | ✅ 支持 a,b,c 参数实时调节 & 自然语言提取 |
| **🧪 化学** | `反应`, `chemistry` | **一级反应动力学** | ✅ 调节反应速率常数 k |
| **📊 统计** | `回归`, `线性` | **线性回归分析** | ✅ 自动生成带噪数据并拟合 |
| **📉 经济** | `供需`, `supply` | **市场供需平衡曲线** | ❌ 静态展示均衡点 |
| **🧬 生物** | `种群`, `biology` | **Logistic 增长模型** | ❌ 对比 J 型与 S 型曲线 |
| **🧊 3D** | `3d`, `曲面` | **复杂数学曲面** | ✅ 3D 旋转、缩放 |
| **💻 算法** | `排序`, `冒泡` | **冒泡排序可视化** | ✅ 实时排序动画演示 |
| **🌊 物理** | `波`, `sin` | **正弦波生成** | ✅ 调节频率 & 支持 "freq 5" 等指令 |

### 6.3 战略价值
1.  **零成本高体验**：覆盖了用户最常测试的高频输入，无需消耗任何 Token。
2.  **即时响应**：无网络延迟，毫秒级出图。
3.  **教育属性**：预设的参数调节功能（如二次函数的系数）使其直接具备了教学演示价值。

### 6.4 持续进化 (2025-12-07 更新)
我们已快速落实了以下增强：
*   **智能参数提取**：Mock 引擎现在能理解自然语言中的数值！
    *   输入 "sin freq 5" -> 自动设置正弦波频率为 5。
    *   输入 "a=2 b=3 c=1" -> 自动设置二次函数系数。
*   **混合模式 (Hybrid Mode)**：在 Mock 结果页增加了 **"✨ AI 优化"** 按钮。
    *   允许用户从离线 Mock 无缝切换到在线 LLM 生成，兼顾速度与灵活性。
