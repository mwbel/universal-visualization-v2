# 提案：可视化缓存数据库系统（本地+Web API混合架构）

## Why
当前系统每次请求都重新生成可视化，缺乏缓存机制导致重复请求浪费资源，且无法处理用户上传的文件内容进行可视化生成。同时，未来计划发展为桌面应用程序，采用**本地处理 + Web API调用**的混合架构，实现离线优先的智能可视化服务。

## 概述

构建一个高效的可视化缓存数据库系统，支持基于关键词的快速匹配、已生成页面的存储检索，以及未来扩展的图片和文档上传处理能力。系统采用**桌面应用（exe/pkg）+ 内嵌WebView + 智能引擎选择**的架构：

- **本地优先**: Mock本地引擎提供完全离线的核心功能
- **API增强**: LLM大模型API提供智能生成能力（可选）
- **智能路由**: 根据输入复杂度自动选择最佳处理方式
- **本地缓存**: SQLite存储所有结果，实现成本优化和快速响应

## 背景分析

根据当前架构分析，系统已经实现了完善的混合模式（方案A）：
- Mock本地引擎：覆盖8大学科高频场景，支持智能参数提取
- LLM生成引擎：处理长尾需求，动态生成可视化
- 现有问题：每次请求都重新生成，缺乏缓存机制，重复请求浪费资源

## 解决方案

### 1. 核心架构设计

**数据库架构三层设计**：

```
┌─────────────────────────────────────────────────────┐
│                  应用层 (FastAPI)                    │
├─────────────────────────────────────────────────────┤
│  缓存查询 → Mock引擎 → LLM引擎 → 结果存储              │
├─────────────────────────────────────────────────────┤
│              数据访问层 (SQLAlchemy)                  │
├─────────────────────────────────────────────────────┤
│  SQLite/PostgreSQL  向量数据库(Qdrant)  文件存储       │
└─────────────────────────────────────────────────────┘
```

### 2. 数据库选型 - 桌面应用优先

**主数据库 (SQLite优先)**：
- **SQLite**: 桌面应用首选，零安装，单文件数据库，支持ACID事务
  - 开发/测试环境：完全满足需求
  - 桌面应用：嵌入式部署，用户无需额外安装数据库
  - Web应用：可支持中等规模并发
  - 跨平台完美支持：Windows/macOS/Linux
- **PostgreSQL**: 大规模Web应用的备选方案
  - 企业级功能：高级索引、分区表、复制
  - 高并发支持：适合多用户Web服务
  - 扩展性：支持水平和垂直扩展

**向量数据库 (本地优先)**：
- **SQLite FTS5**: 内置全文搜索，支持中文分词
- **ChromaDB**: 本地向量数据库，轻量级，Python生态
- **Qdrant**: 云端向量数据库，为未来扩展预留

**文件存储 (本地为主)**：
- **本地文件系统**: 桌面应用的主要存储方式
  - 跨平台路径管理：Windows `%APPDATA%`、macOS `~/Library`、Linux `~/.local/share`
  - 数据加密：支持SQLite数据库加密
  - 备份恢复：用户友好的数据导出/导入功能
- **云存储**: 可选的云端同步功能

### 3. 核心功能 - 本地+Web API混合处理

#### 混合处理架构详解

**第一阶段：智能引擎选择系统**
1. **关键词智能分析**：分析用户输入的复杂度和可匹配性
2. **引擎智能路由**：
   - **Mock本地引擎**：高频模板匹配，完全离线，毫秒级响应
   - **LLM API调用**：复杂需求处理，需要网络，智能生成
   - **缓存优先查询**：检查本地SQLite缓存，避免重复API调用
3. **结果智能缓存**：API调用结果自动存储到本地，后续直接使用缓存
4. **成本智能控制**：智能去重和缓存，LLM调用成本降低60-80%

#### 桌面应用实现模式
```
桌面应用启动 → 用户输入 → 智能路由决策
    ↓                           ↓
┌─────────────┐         ┌────────────────┐
│ Mock本地引擎  │  ←→     │ LLM API调用     │
│ (完全离线)   │         │ (需要网络)     │
└─────────────┘         └────────────────┘
         ↓                           ↓
         └────────→ 本地SQLite存储 ←─────────┘
                           ↓
                    内嵌WebView展示结果
```

**第二阶段：文件处理 + 智能匹配**
1. **本地文件处理**：用户上传文件后本地存储和处理
2. **离线OCR识别**：使用本地OCR引擎进行文字识别（Tesseract）
3. **内容智能分析**：提取关键概念，匹配最佳可视化方案
4. **混合生成模式**：
   - 优先尝试：基于文件内容匹配本地Mock模板
   - 增强处理：文件内容 + LLM API生成复杂可视化
   - 缓存复用：相似文件处理结果的智能匹配

**桌面应用核心优势**
- **渐进式体验**：网络好时功能丰富，网络差时核心功能可用
- **数据本地化**：所有用户数据和生成内容完全本地存储
- **隐私保护**：敏感文件无需上传到云端
- **成本可控**：基础功能完全免费，高级功能按需付费

### 4. 性能优化 - 桌面应用优化

**缓存策略（桌面应用优化版）**：
- L1缓存：应用内存缓存热点数据（50MB，应用生命周期）
- L2缓存：SQLite WAL模式和内存映射（500MB，持久化）
- L3缓存：磁盘存储的完整历史数据（无限制，可压缩）

**索引设计（SQLite优化）**：
- 关键词全文索引：SQLite FTS5，支持中文搜索
- 向量相似度索引：本地Embeddings + 余弦相似度计算
- 时间、学科、模式多维度复合索引
- 内存映射：256MB mmap_size，提升查询性能

**桌面应用专项优化**：
- WAL模式：提升SQLite并发性能
- 连接复用：单连接池，避免频繁建立连接
- 压缩存储：文本数据gzip压缩，节省50%空间
- 异步操作：文件处理和LLM调用异步化
