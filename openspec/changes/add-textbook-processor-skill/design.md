# Textbook Processor Skill - Design Document

## Context

### 背景
项目需要处理大量数学教材 PDF，包括：
- 线性代数教材
- 概率统计教材
- 微积分教材
- 其他数学相关教材

### 当前问题
1. 手工按章节切分 PDF 耗时且容易出错
2. PDF 格式不利于知识点检索和溯源
3. 缺乏统一的教材处理流程
4. 目录识别依赖人工，不够自动化

### 约束条件
- PDF 可能是文字版或 OCR 版
- 教材格式不统一（中文、英文）
- 目录结构复杂（章、节、小节）
- 需要保持公式、图片、表格的完整性

## Goals / Non-Goals

### Goals
- ✅ 自动识别 90% 以上的标准教材目录结构
- ✅ 按章节准确切分 PDF（误差 < 1 页）
- ✅ 保留 Markdown 中的数学公式（LaTeX 格式）
- ✅ 生成结构化的元数据（JSON 格式）
- ✅ 支持批量处理多本教材

### Non-Goals
- ❌ 自动识别知识点（由其他系统处理）
- ❌ 内容质量评估（由人工复核）
- ❌ 多语言翻译（仅处理中英文）
- ❌ 在线预览（生成文件即可）

## Decisions

### Decision 1: PDF 目录识别策略

**选择：混合策略（优先 PDF 内置 TOC + 回退到文本识别）**

**理由：**
- 大部分正式教材有内置 TOC，准确率最高
- 对于没有 TOC 的 PDF，使用正则表达式匹配章节标题
- 常见章节模式：`第X章`、`Chapter X`、`X.` 等

**替代方案：**
- 仅依赖 PDF TOC：失败率高
- 仅依赖 OCR：准确率低且速度慢
- 人工标注：不 scalable

**实现：**
```python
# 伪代码
def extract_toc(pdf):
    # 优先使用内置 TOC
    toc = pdf.get_toc()
    if toc:
        return toc

    # 回退到文本识别
    for page in pdf.pages:
        text = extract_text(page)
        if match_chapter_title(text):
            add_to_toc(page_num, text)
```

### Decision 2: PDF 切分工具

**选择：PyMuPDF (fitz)**

**理由：**
- 性能优秀（比 PyPDF2 快 5-10 倍）
- API 简洁直观
- 支持多种 PDF 格式
- 活跃维护

**替代方案：**
- PyPDF2：性能较差，API 复杂
- pdfplumber：适合表格提取，但切分 PDF 不是强项

### Decision 3: PDF 到 Markdown 转换

**选择：MinerU (magic-pdf)**

**理由：**
- 专门为学术 PDF 设计
- 数学公式保留效果好（LaTeX 格式）
- 表格和图片识别准确
- 开源且持续更新

**替代方案：**
- pdf2md：公式支持差
- Mathpix：商业化，需要 API key
- 自研方案：开发成本高

### Decision 4: 文件组织结构

**选择：按书分目录，章节分开存储**

```
processed/
└── {书名}/
    ├── original/
    │   └── {书名}.pdf
    ├── chapters/
    │   ├── 第1章_xxx.pdf
    │   └── ...
    ├── markdown/
    │   ├── 第1章_xxx.md
    │   └── ...
    ├── metadata.json
    └── index.html
```

**理由：**
- 清晰的层级结构
- 便于管理和查找
- 支持增量处理

## Risks / Trade-offs

### Risk 1: 目录识别失败
- **风险：** 某些 PDF 没有标准目录格式
- **缓解：** 提供手动标注工具作为补充
- **降级：** 按固定页数切分（如每 50 页一章）

### Risk 2: MinerU 转换失败
- **风险：** 部分 PDF 格式特殊，转换失败
- **缓解：** 记录失败日志，支持重试
- **降级：** 保留原 PDF 文件

### Risk 3: 数学公式丢失
- **风险：** 复杂公式可能转换不完整
- **缓解：** 优先使用 LaTeX 格式
- **降级：** 保留公式截图

### Risk 4: 大文件处理性能
- **风险：** 大型教材（>1000 页）处理时间长
- **缓解：** 支持分批处理和断点续传
- **降级：** 限制单文件最大页数

## Open Questions

1. **Q:** MinerU 是否需要本地安装还是可以使用远程 API？
   - **A:** 建议本地安装，避免网络依赖和 API 限流

2. **Q:** 如何处理跨页的图表和公式？
   - **A:** 尝试合并相邻页，或保留为图片引用

3. **Q:** 是否需要支持增量更新（重新处理已修改的章节）？
   - **A:** 初期不支持，后续可根据需求添加

4. **Q:** 元数据格式是否需要与现有知识系统对接？
   - **A:** 需要查看现有知识系统的数据格式

## Performance Considerations

### 预期性能
- 目录识别：< 5 秒（500 页教材）
- PDF 切分：< 10 秒
- MinerU 转换：约 1-2 秒/页

### 优化策略
- 并行处理多个章节
- 缓存已处理结果
- 支持断点续传

## Success Metrics

- 成功识别目录率 > 90%
- PDF 切分准确率 > 99%
- MinerU 转换成功率 > 95%
- 处理速度 > 30 页/分钟
