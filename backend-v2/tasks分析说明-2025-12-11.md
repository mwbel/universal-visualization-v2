# 📋 项目任务分析说明

> 面向小白用户的任务目的和关联分析

*创建日期: 2025-12-11*

---

## 🏗️ 整体理解：建一个智能可视化"工厂"

把整个项目想象成建造一个"**智能可视化工厂**，能够根据用户需求生成各种图表和动画。

**工厂的核心流程**：
```
用户需求 → 智能分析 → 生成产品 → 存储产品 → 下次直接取用
```

---

## 📊 项目阶段总览

### 第一阶段：核心缓存系统 (Week 1-5)
**目标**：让工厂能够"记住"做过的产品，避免重复劳动

### 第二阶段：文件处理系统 (Week 6-10)
**目标**：让工厂能够"读懂"用户上传的文件并生成对应产品

### 第三阶段：桌面应用打包 (Week 11-15)
**目标**：把工厂打包成可安装的软件

---

## 🔧 第一阶段：核心缓存系统详细分析

### 🏗️ 数据库基础设施 (地基建设)

#### ✅ Task 1: 设置SQLite开发环境 (打地基)
**小白理解**：
- 就像建房子要先打地基
- SQLite就是一个轻量级的"数据库文件柜"
- SQLAlchemy是"数据库操作工具包"

**目的**：建立数据存储的基础设施
- 安装工具包 (就像买装修工具)
- 创建数据库连接 (就像接通水电)
- 测试连接 (确保水管电线正常)

**关联关系**：
```
Task 1 → Task 2 → Task 3 → Task 4 → Task 5 → Task 6...
   ↓       ↓       ↓       ↓       ↓
 地基    设计     迁移     入库     测试
```

#### ✅ Task 2: 设计并创建数据库Schema (设计仓库结构)
**小白理解**：
- 设计仓库怎么分区
- 哪存区放什么，加工区放什么，成品区放什么

**目的**：创建数据存储的"货架布局"
- visualization_records (产品货架)：存储生成的可视化
- visualization_templates (模板货架)：存储预制菜谱
- keyword_index (目录卡片)：存储关键词索引

**关联关系**：依赖Task 1的数据库连接

#### ✅ Task 3: 数据库迁移脚本 (安装升级系统)
**小白理解**：
- 就像房子的装修日志
- 记录每次改动了什么结构
- 能升级也能降级

**目的**：建立版本控制机制
- 创建迁移工具 (装修记录本)
- 实现版本管理 (支持回退)

**关联关系**：依赖Task 2的数据库设计

### 📦 MockEngine数据迁移 (入库原料)

#### ✅ Task 4: 导入MockEngine模板数据 (搬入预制菜谱)
**小白理解**：
- MockEngine就是"老菜谱本"
- 现在要把它数字化存入仓库
- 方便后续查找和使用

**目的**：将现有模板系统化
- 解析现有的模板代码
- 转换为数据库格式
- 建立模板管理系统

**关联关系**：依赖Task 3的迁移工具

#### ✅ Task 5: 生成测试数据 (准备测试样品)
**小白理解**：
- 新工厂建成后要"试运行"
- 制作一些标准产品验证流程
- 确保各个部门协调正常

**目的**：验证系统功能完整性
- 创建各学科的示例数据
- 测试存储和查询功能
- 验证缓存效果

**关联关系**：依赖Task 4的模板数据

### 🤖 核心缓存服务 (智能系统)

#### ✅ Task 6: 实现关键词提取服务 (安装智能大脑)
**小白理解**：
- 就像给工厂安装"智能助手"
- 能听懂用户需求并分类
- 知道用户想要什么类型的产品

**目的**：建立智能分析能力
- 识别用户输入的关键词
- 自动分类到相应学科
- 实现同义词识别

**关联关系**：依赖Task 2的数据库结构，为后续搜索做准备

#### ⏳ Task 7: 集成向量embeddings (安装语义理解系统) **(待开始)**
**小白理解**：
- 现在只能"精确匹配"关键词
- 想要让系统"理解意思相近"的需求
- 比如"画圆"和"生成圆形图像"应该能匹配

**目的**：实现语义搜索能力
- 将关键词转换为数字向量
- 计算语义相似度
- 支持模糊搜索

**关联关系**：依赖Task 6的关键词提取，提供搜索基础

#### ⏳ Task 8: 实现缓存查询核心逻辑 (建立智能调度系统) **(待开始)**
**小白理解**：
- 建立"智能调度员"
- 用户要找东西时，系统会：
   - 先查短期记忆 (内存缓存)
  - 再查中期记忆 (SQLite缓存)
  - 最后查完整记录 (数据库)

**目的**：建立多级缓存机制
- 实现快速响应
- 优化用户体验
- 减少重复计算

**关联关系**：依赖Task 6(关键词)和Task 7(向量)，需要搜索能力

#### ⏳ Task 9: 实现语义搜索功能 (增强搜索能力) **(待开始)**
**小白理解**：
- 现在不仅支持"精确匹配"
- 还能"模糊搜索"和"语义搜索"
- 用户说"想要图表"，能找到所有相关的模板

**目的**：提升搜索准确度
- 集成向量相似度算法
- 支持模糊匹配
- 提高搜索成功率

**关联关系**：依赖Task 7的向量化能力

#### ⏳ Task 10: 实现缓存存储服务 (建立仓库管理系统) **(待开始)**
**小白理解**：
- 建立"仓库管理员"
- 新产品生产出来后要：
  - 贴存到合适的位置
  - 设置过期时间
  - 定期清理过期产品

**目的**：完善存储管理
- 自动存储新结果
- 实现缓存过期机制
- 优化存储空间

**关联关系**：依赖Task 8的缓存查询，知道何时需要存储

### 🌐 API接口集成 (对外开放服务窗口)

#### ⏳ Task 11: 实现缓存查询API端点 (开设服务窗口) **(待开始)**
**小白理解**：
- 工厂建好后要开设"服务窗口"
- 用户通过API调用工厂服务
- 提供标准化的接口

**目的**：暴露缓存查询能力
- POST /api/v2/cache/search (按关键词搜索)
- POST /api/v2/cache/semantic-search (语义搜索)
- GET /api/v2/cache/stats (获取统计信息)

**关联关系**：依赖Task 9的搜索功能，需要有东西可以搜索

#### ⏳ Task 12: 实现缓存管理API (管理功能) **(待开始)**
**小白理解**：
- 提供"仓库管理工具"
- 管理员可以通过API：
  - 清理过期产品
  - 预热热门模板
  - 查看仓库状态

**目的**：提供管理功能
- DELETE /api/v2/cache/cleanup (清理缓存)
- POST /api/v2/cache/preload (预加载)
- 监控系统状态

**关联关系**：依赖Task 10的存储机制

#### ⏳ Task 13: 修改/api/v2/generate接口 (整合现有服务) **(待开始)**

**目的**：集成到现有系统

#### ⏳ Task 14: 修改高中课程API (特定业务集成) **(待开始)**

**目的**：扩展业务覆盖

### 🔄 实施流程策略

1. **按阶段推进**：必须完成当前阶段所有任务才能进入下一阶段

3. **质量优先**：每个任务都有明确的验证标准

## 💡 给小白的建议

### 🤔 为什么这样安排任务？

1. **循序渐进**：从基础到高级，稳扎稳打
2. **分层设计**：每层都为上层提供支持
3. **质量保证**：每步都有验证标准
4. **实用导向**：每个任务都有实际价值

### 🔍 如何理解任务关联？

- **纵向依赖**：同一阶段内的任务顺序固定
- **横向扩展**：不同阶段可以并行准备
- **核心价值**：每个阶段都能独立交付价值
